## 📋 角色定义

| 角色 | 职责 | 输入来源 | 输出去向 |
|------|------|----------|----------|
| 🎯 产品策划 | 市场分析、功能规划、需求定义 | 用户反馈、市场调研 | 产品经理 |

| 🔍 QA | 测试验证、质量把关、Bug报告 | 程序 | 产品经理 |

## 🔗 上下游依赖

### 1. 产品策划 → 产品经理
- **交付物**: `FEATURE_SPECS.md` 功能规格说明
- **触发条件**: 策划完成功能设计
- **状态流转**: `planning` → `ready_for_pm`

### 2. 产品经理 → UI设计师
- **交付物**: `TASK_BACKLOG.md` 任务清单 + 功能需求
- **触发条件**: PM完成任务拆解和优先级排序
- **状态流转**: `ready_for_pm` → `ready_for_design`

### 3. UI设计师 → 程序
- **交付物**: 设计稿、切图、设计规范
- **触发条件**: 设计完成并通过评审
- **状态流转**: `ready_for_design` → `ready_for_dev`

### 4. 程序 → QA
- **交付物**: 代码变更 + `CHANGELOG.md`
- **触发条件**: 开发完成并自测通过
- **状态流转**: `ready_for_dev` → `ready_for_qa`

### 5. QA → 产品经理
- **交付物**: `TEST_REPORT.md` 测试报告
- **触发条件**: 测试完成（通过或有Bug）
- **状态流转**: `ready_for_qa` → `done` 或 `has_bugs`

## ⏰ 迭代周期

- **频率**: 每1小时
- **流程**: 按上下游顺序依次执行
- **顺序**: 策划 → 产品 → UI设计 → 程序 → QA
- **条件**: 上游完成才能触发下游

## 🆕 新增角色：UI设计师

### 职责范围
- 界面设计（视觉设计、布局设计）
- 交互设计（用户流程、操作反馈）
- 设计规范制定（色彩、字体、间距）
- 切图和设计资源输出

### 协作流程
1. **接收需求**: 从产品经理获取功能需求
2. **设计初稿**: 快速出低保真原型
3. **评审修改**: 与产品、开发评审
4. **定稿输出**: 高保真设计稿 + 切图
5. **开发跟进**: 解答实现问题

### 交付物
- 设计稿（Figma/Sketch/蓝湖链接）
- 设计规范文档
- 切图资源（SVG/PNG）
- 交互说明文档
